# Implementation scope

[Project home](../README.md) · [Build and content workflow](website-workflow.md)

Stack Menu provides 14 curated component profiles across web applications, services, command-line tools, automation and native mobile. The human page is a small entry; agent guidance includes selection, chosen-stack building and explicit migration workflows, complete Markdown/JSON records and source references.

The optional context router validates explicit requirements and returns resources, candidates, exclusions and questions. It calls no model and stores no application data. Known-stack work preserves the choice; new-stack comparisons and migration planning keep constraints and unknowns explicit. The visiting agent interprets the application conversation and reasons about the result.

Initial HTML, matching page Markdown, JSON exports, canonical sitemap, crawler policy and factual contact resources support ordinary browsing and direct retrieval. Production uses Cloudflare Pages with Functions; local responses have noindex headers and exclude analytics. Aggregate pageviews load only on the canonical production origin. The preview uses the same routing and format handlers.

Core official guidance and all 394 cited source addresses were checked on 13 October 2026. Original research dates and check scope remain separate in the [freshness snapshot](../menu/inputs/research/freshness.json). Recipes, full dependency combinations, application capacity and migrations require qualification in the actual project; this reference does not certify compatibility or measured cross-stack rankings.

Build and local rendered/direct checks cover desktop and phone views, contact representations, routing, malformed input, true missing pages and resource parity. These are website checks, not execution evidence for every application recipe. Demo media and a final designer identity are pending.

## Generator guidance — 18 October 2026

All 14 curated profiles now have first-party [generator records](../menu/generators/README.md): official framework/language initializers, IDE templates or documented CLI routes, conditional incremental generators, generated defaults to retain and baseline checks. Plain Mix project choices are included with the Phoenix profile; supervision is conditional. Profiles without a full application generator explicitly distinguish module/package initialization from the application code still needed.

The [shared workflow](../content/generation-policy.json) requires generation before hand-authoring a new skeleton, preserves existing repositories, records deviations and separates review from execution. Agent entry guidance links the rules. The normal compiler exposes matching HTML, complete Markdown, structured records, the full bundle and `/generators.json`, and requires coverage for every curated profile. Generator review dates remain distinct from imported research freshness.

Commands and native templates are documentation-reviewed, not executed or application-qualified. Stack Menu can provide explicit instructions and a generation receipt; enforcement in a consuming agent or build runner requires that consumer to honor and verify the guidance.

Local verification on 18 October: normal build passed; all 14 profiles passed direct checks for source/record/catalogue agreement, command coverage in HTML, complete and negotiated Markdown and the full bundle, MIME, `Vary: Accept`, HEAD, local noindex and genuine missing-page status. The catalogue includes 22 starting points, 34 conditional follow-up entries and 85 unique cited sources. Desktop browser inspection of the Elixir generator section passed; phone rendering was not inspected in this pass. An independent read-only integration review found no actionable defects. These checks verify reference delivery, not application scaffolding execution.
